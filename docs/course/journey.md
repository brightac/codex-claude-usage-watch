# 从零做一个真产品：AI 结对开发全过程

> 这是 `codex-claude-usage-watch` 的**真实开发实录**，从"我想看额度"一句话需求，到一个能开机自启、带毛玻璃 HUD、上架 GitHub 的 macOS 工具。
>
> 它适合作为"**用 AI 编码工具（Claude Code / Codex）做第一个 web/桌面产品**"的教学案例——因为它不是被剪辑过的完美 demo，而是**带着真实的踩坑、调试、返工和用户反馈**的过程。每一集都对应一个真实的 git commit。

---

## 课程主线（一句话）

**需求 → 逆向找数据 → 命令行原型 → 合并两家 → 打磨终端体验 → 走向原生 GUI → 用截图迭代设计 → 抓真 bug → 做可发现性 → 上架开源。**

## 第 0 集 · 需求从"痛"开始

**起点**：一句话——"我想实时看 Claude Code 在 5 小时窗口和一周窗口的 token 剩余，能自动刷新。这是 codex 的版本（贴出一个已有脚本）。"

**教学点**：
- 好产品从**自己的真实痛点**来，而不是"想做个 App"。
- 给 AI 一个**参照物**（已有的 codex 脚本）能极大降低沟通成本——"照着这个，做 Claude 版"。

---

## 第 1 集 · 逆向：数据到底在哪儿？

这是最"侦探"的一集，也是最能体现 AI 编码工具价值的一集。

我们要找 Claude Code 的额度数据，依次排除：
- `~/.claude/` 下没有落盘的额度数据；
- 项目 jsonl 里的 "unified" 只是 "unified diff"，虚惊一场；
- 最终定位到 **`/api/oauth/usage`**（和会话里 `/usage` 命令同源），鉴权用 **钥匙串里的 OAuth token**。

**教学点**：
- AI 可以**读二进制、翻钥匙串、grep 端点**，几分钟做完人工要几小时的逆向。
- **不要臆测数据格式**——去找真实来源、真实字段。这一集埋下的坑（`utilization` 单位）第 8 集才爆。

---

## 第 2 集 · 命令行原型（Initial release）

`commit: Initial release`

先做能跑的最小闭环：读钥匙串 → 调接口 → 打印 5h/7d 两个窗口 → 定时刷新。

**教学点**：
- **先跑通一条线**，再谈体验。
- 关键决策当场拍板（Node 单文件、无依赖、`--once`/`-i` 参数），不纠结。

---

## 第 3 集 · 合并两家（Codex + Claude 同屏）

用户："把 codex 也加上。" 于是把两个来源合并成一个 `usage-watch`：
- Codex 走本机 `codex app-server` 的 JSON-RPC；
- Claude 走 `/api/oauth/usage`；
- 两边**独立容错**——一边挂了另一边照常显示。

**教学点**：**容错要在架构层设计**（`Promise.allSettled`），而不是事后打补丁。

---

## 第 4 集 · 打磨终端体验

一连串"看起来小、其实很影响手感"的问题，全部来自用户的真实吐槽：
- "单行模式不是单行" → 原来是跑错脚本 + 真的没实现 `--line`；
- "刷新一直往上刷屏" → `\x1Bc` 整屏 reset 会把旧画面塞进滚动历史，改成**光标归位 + 原地覆盖**；
- "56% 和 9% 错位了" → 百分比**右对齐补齐**；
- "钟表时间也对齐" → 时长做**定宽格式化**；
- 加**磁盘缓存**：撞限流（429）时显示 `(cached Xm ago)` 而不是 unavailable。

**教学点**：
- **终端 UI 也是 UI**，转义码、对齐、宽度都要抠。
- 很多"bug"其实是**沟通误会**（跑错脚本）——先复现，再动手。

---

## 第 5 集 · 走向原生：第一个 GUI 产品

用户："我想做成 Mac 桌面上一个半透明浮动窗口。"

这是从"脚本"跨到"产品"的一集。选型后用 **Swift + AppKit** 写单文件 HUD，`swiftc` 直接编译，不依赖任何第三方 App：
- 无边框、毛玻璃、始终置顶、可拖动、位置记忆；
- 每 300 秒跑一次 `usage-watch --once` 填充。

**教学点**：
- AI 让你**跨技术栈**几乎零成本——不会 Swift 也能做原生 App。
- **复用已有能力**：HUD 不重造轮子，直接调用已经做好的 CLI。

---

## 第 6 集 · 用截图迭代设计

这一集是"人机协作"的精华：**用户截图 → AI 修**，一轮轮逼近想要的效果。

真实发生过的往返：
- "高度不够看不全" → 改用**行数×行高**精确测高；
- "只能放深色背景" → 加**固定深色底 + 强制暗色外观**，任何壁纸都清晰；
- "进度条太长把内容顶到换行" → 进度条从 22 格缩到 12 格；
- "有 used、left 都没必要，我只想看还剩多少" → 砍掉 used，进度条改**油量表**（满=剩得多）；
- "字和图形重复了" / "中间数字加 %" / "套餐显示 Pro 20×、Max 20×"；
- "背景要更透" → 加**可调透明度**菜单（Clear/Light/Medium/Solid）；
- "四个角的矩形阴影露出来了" → `maskImage` 圆角遮罩让窗口阴影跟着圆角。

**教学点**：
- **一张截图胜过一百字**。教学时要示范：怎么给 AI 反馈视觉问题。
- AI 看不到你的屏幕——**你是它的眼睛**，要如实描述、发图。

---

## 第 7 集 · 可发现性：菜单栏

用户："这个浮窗没有菜单，别人不知道怎么用、有什么快捷键。"

加**菜单栏图标**（显示最紧张的剩余额度）+ 点击/右键菜单：列出每个窗口 + 所有操作和快捷键（⌘T 切皮肤 / ⌘R 刷新 / 退出）+ 数据"更新于/下次更新"时间。

**教学点**：**功能做完 ≠ 产品做完**。用户不知道怎么用 = 没做完。可发现性是产品的一部分。

---

## 第 8 集 · 抓真 bug（本课最值钱的一集）

三个层层递进的真实 bug，全靠**和权威数据源对照**才抓出来：

1. **`utilization` 单位错**（`commit: don't ×100`）
   官方面板显示"5 小时用了 1%"，我的工具却显示"剩 0%"。查原始 API：`utilization=2.0` 本就是 2%（百分比），我却写了 `if util<=1 则 ×100`——把 1% 当成 100%。**只在用量 ≤1% 时才暴露**，极隐蔽。

2. **登录命令给错了**
   新机器首装，Claude 报 `refresh HTTP 400`。深查发现：`claude setup-token` 生成的是环境变量 token，**不写钥匙串那个 `claudeAiOauth` 条目**，而工具只读它。正确命令是 `claude auth login`。README 和报错提示全部改对。

3. **Codex 数据"不准"其实是限制结构变了**
   Codex 5h 和 7d 显示成一样的值。一开始我怀疑 app-server 不稳（确实也不稳），深挖后用户一句话点破：**"Codex 今天取消了 5 小时限制。"** app-server 现在把周数据放在 `primary` 槽，而我**硬编码** `primary→5h`。改成**按窗口实际时长（`windowDurationMins`）打标签**，Codex 就只显示 7d 了。

**教学点**：
- **永远和 ground truth 对照**（官方面板 = 真值）。数字"看着对"不代表对。
- **别急着甩锅给外部**——先怀疑自己的解析。这一集我一度说"是 app-server 的锅"，用户坚持"你去查查"，结果根因在我这边（旧结构解析）。
- **用户的领域知识**（"Codex 取消了 5h 限制"）常常是解 bug 的钥匙。

## 第 9 集 · 上架开源

- `install.sh`：一键装 CLI + 编译 HUD + 配 LaunchAgent 开机自启；支持 `--no-hud` / `--uninstall`。
- 发布前清理硬编码用户名、把路径改成 `$HOME`。
- 写 README（含鉴权原理、限流缓存说明）、MIT LICENSE。
- **在另一台电脑首装验证**——真正跑通才算数，并借此发现了第 8 集的登录 bug。

**教学点**：**"能在我机器上跑"不算完**。可移植、可安装、别人能用，才是产品。

## 尾声 · 怎么和 AI 编码工具协作（元技能）

这门课真正想教的，是**协作方式**：

1. **给参照物**：贴一个类似的现成东西，让 AI 照着做。
2. **先跑通再打磨**：别一上来追求完美。
3. **你是 AI 的眼睛**：截图、贴报错、描述现象。
4. **和真值对照**：官方数据、另一台机器、实际运行——别信"看着对"。
5. **坚持你的直觉**："我觉得脚本有问题，你去查查"——往往是对的。
6. **领域知识是钥匙**：你懂的业务背景（限制变了），AI 不一定知道。
7. **每一步都提交**：git log 就是你的开发日志，也是这门课的骨架。
